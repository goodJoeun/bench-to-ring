# 농구 선수 키우기

**벤치 뎁혀 반지 굽기**

고교 벤치 멤버로 시작해 KBL과 NBA를 거쳐 MVP와 우승 반지에 도전하는 농구 커리어 시뮬레이션 게임이에요. 은퇴한 선수는 온라인 랭킹에 올라가 다른 플레이어의 선수와 순위를 겨뤄요(https://www.bench2ring.com).

리그와 구단은 2026-27 시즌 기준 실제 명칭을 써요(`src/game/world/leagues.ts`). 비공식 팬 게임이고, 명칭과 로고의 권리는 각 권리자에게 있어요. 구단·학교 로고는 실제 로고 파일을 `public/logos/`에 넣으면 그대로 보여줘요(아래 "로고 넣기"). 로고 파일이 없는 팀은 이름과 대표색으로 만든 자체 엠블럼(`src/shared/ui/badge/emblem.ts`)을 보여줘요. 엠블럼은 리그마다 바탕 모양이 다르고(NBA 원형, KBL 방패, G리그 육각형, 유로리그·U-리그 문장, NCAA 뾰족 방패, 고교 깃발), 가운데에는 SK·LG·셀틱·용산 같은 약칭이 들어가요. 실존 선수는 플레이 유형 예시, 은퇴 화면의 역대 기록 순위표(`src/game/legacy/records.ts`, 2025-26 시즌 종료 기준)와 닮은 꼴 선수(`src/game/legacy/comps.ts`)에만 나와요.

## 실행하기

Node.js 20.9 이상이 필요해요.

```bash
npm install
npm run dev
```

브라우저에서 http://localhost:3001 을 열면 돼요.

게임은 DB 없이도 할 수 있어요. 은퇴 기록 등록과 랭킹 페이지(`/rankings`)를 쓰려면 Postgres 연결이 필요해요(아래 "온라인 랭킹").

1. `.env.example`을 `.env.local`로 복사하고 값을 채워요. 값은 커밋하지 않아요.
   - `DATABASE_URL`: 게임 서버용 Supabase 연결 문자열 (대시보드 Connect의 Transaction pooler, 포트 6543)
   - `DATABASE_URL_UNPOOLED`: 마이그레이션·스크립트용 연결 문자열 (Session pooler, 포트 5432)
   - `TOKEN_SECRET`: 플레이어 토큰 해시에 쓰는 비밀 값. `node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"`로 만들어요.
   - `RESEND_API_KEY`, `FEEDBACK_TO`: 의견 보내기 메일. [Resend](https://resend.com) API 키와 의견을 받을 주소예요. 도메인을 인증하기 전에는 Resend 가입 메일 주소로만 보낼 수 있어요. 비어 있으면 의견 보내기가 "지금은 의견을 보낼 수 없어요"로 끝나요.
2. `npm run db:migrate`로 테이블을 만들어요.

배포 DB는 Supabase 서울 리전 프로젝트예요. 로컬에서 배포 DB에 연결하면 실제 기록이 바뀌니 조심해요.

| 명령 | 하는 일 |
| --- | --- |
| `npm run dev` | 개발 서버 실행 |

| `npm run balance` | 밸런스 리포트 (커리어 600개의 나이별 오버롤, NBA 진출률, MVP 비율) |

## 로고 넣기

1. `npm run logos`를 실행하면 로고가 없는 팀의 정확한 파일 이름이 리그별(고교, U-리그, NCAA, KBL, G리그, 유로리그, NBA, 아시아·유럽·캐나다의 대학·프로 리그, 국가대표, 군 부대)로 나와요. 이 목록을 보며 로고를 준비해요.
2. 원본 로고를 `logos-src/`에 넣어요. 크기와 형식(PNG·JPG·WebP·SVG·GIF)은 상관없고, 파일 이름만 게임 속 이름과 똑같이 지어요. NBA 구단은 영문 팀 이름이 들어 있으면 그대로 넣어도 돼요(예: `boston_celtics_logo_primary.png` → 보스턴 셀틱스). 영문 이름 표는 `scripts/logos.mjs`의 `ALIASES`에 있어요.
   - 구단·학교: `src/game/world/leagues.ts`의 이름 그대로. 예: `보스턴 셀틱스.svg`, `서울 SK 나이츠.png`, `용산고.png`
   - 국가대표: 나라 이름. 예: `대한민국.png`
   - 군 부대: `상무 (국군체육부대).png`, `육군 (현역 복무).png`
3. `npm run dev`(또는 `npm run logos`)를 실행하면 원본을 **128×128 투명 PNG**로 바꿔 `public/logos/`에 게임 속 이름으로 저장해요. 흰 배경 위에 그려진 로고는 가장자리에 붙은 흰 배경을 지우고(로고 안쪽 흰색은 남겨요), 둘레 여백을 잘라내고, 비율을 지킨 채 가운데에 맞추고, 가장자리에 6px 여백을 둬요. 원본과 변환 스크립트가 바뀌지 않았으면 다시 변환하지 않아요. 이어서 `src/shared/ui/badge/logos.generated.ts`를 다시 만들고, 연결된 로고 수와 이름이 맞지 않는 파일, 64px보다 작아 흐릴 수 있는 원본을 알려줘요.
4. 로고가 있는 팀은 선수 카드, 결정 선택지, 경기 기록, 드래프트, 결승 중계 등 엠블럼이 나오던 모든 곳에서 로고로 바뀌어요.
5. 리그 우승 팝업의 리그 로고는 `logos-src/leagues/<리그 키>.png`에 넣으면 `public/leagues/`로 바뀌어요. 출처는 [docs/league-logos.md](docs/league-logos.md)에 있어요.

흰색이 아닌 배경(검정, 색 배경)은 지우지 않으니 배경이 투명한 PNG나 SVG 원본이 가장 깔끔해요. 어두운 테마와 파란 진행 팝업에서는 어두운 로고도 잘 보이게 밝은 타일 위에 올려 보여줘요. 이미 128×128로 준비한 파일은 `public/logos/`에 바로 넣어도 돼요(변환하지 않고 그대로 써요).

로고는 각 구단·리그·학교의 상표예요. 사용 허락을 받았거나 쓸 수 있는 파일을 넣어 주세요. 저장소에 올리지 않고 내 컴퓨터에서만 쓰려면 `.gitignore`에 `logos-src/*`, `public/logos/*`, `!logos-src/.gitkeep`, `!public/logos/.gitkeep`을 더하고, `logos.generated.ts`의 변경도 커밋하지 않으면 돼요.

## 국기

국가대표 대회의 대표팀은 둥근 국기로 보여줘요. 국기는 [flag-icons](https://github.com/lipis/flag-icons) 7.5.0(MIT, 라이선스는 `public/flags/LICENSE`)의 정사각형 SVG이고, 게임에 나오는 나라(`src/game/world/national.ts`의 대표팀과 대회 상대국)의 국기만 `public/flags/`에 복사해요. 상대국을 늘리면 `scripts/flags.mjs`의 `CODES`에 나라 이름과 국가 코드를 더하세요. 코드가 없는 나라는 `npm run flags`가 알려주고, 그동안은 엠블럼으로 보여줘요. 대만은 국제 대회에 차이니즈 타이베이 깃발로 나오는데 flag-icons에 그 깃발이 없어서 엠블럼(TPE)으로 보여줘요.

## 구조

기능 중심 구조예요. 게임 규칙(엔진)은 화면과 떨어진 순수 TypeScript라 테스트하기 쉽고, 서버에서도 그대로 써요(기록 검사, 랭킹 점수). 폴더마다 하는 일, 의존 방향(`app → features → shared → game`), 새 파일 둘 곳은 [docs/architecture.md](docs/architecture.md)에 정리해 두었어요.

```
drizzle/                   마이그레이션 SQL (npm run db:generate가 만들어요)
src/
├─ app/                    라우트만: 페이지, 레이아웃, Route Handler(아래 "온라인 랭킹"의 API), 전역 스타일
├─ features/               화면 기능
│  ├─ shell/               Game.tsx: 화면 전환(선수 생성 / 커리어 / 시즌 결산 / 은퇴), 상단 메뉴, 진행 팝업 띄우기
│  ├─ create/              첫 화면(표지)과 단계별 선수 생성
│  ├─ career/              커리어 진행 화면 (코트 카드, 전광판, 시즌 진행, 투자, 계약, 상점, tabs/)
│  ├─ season-end/          시즌 결산 화면 (시즌 리포트·순위표·커뮤니티, 시즌과 오프시즌 사이)
│  ├─ progress/            진행 팝업 (국가대표 대회·드래프트·결승 중계·응원·은퇴 회고)
│  ├─ retired/             은퇴 화면, 역대 기록 순위, 기록 카드 공유
│  ├─ rankings/            랭킹 페이지 (베스트 5, 랭킹 100, 포지션별, 스탯 랭킹, 나의 기록)
│  ├─ hall-of-fame/        명예의 전당
│  ├─ notice/              공지 창과 공지 글 목록 notices.ts (새 글은 맨 위에 추가)
│  ├─ achievements/        업적 창
│  └─ feedback/ · guide/ · settings/ · support/   의견 보내기, 게임 안내, 설정, 서버비 후원
├─ shared/                 여러 기능이 같이 쓰는 것
│  ├─ ui/                  Panel·StatTiles 같은 UI, 시트, 토스트
│  │  ├─ sprite/           Canvas 선수 캐릭터, 표지 그림, 기록의 캐릭터
│  │  └─ badge/            국기·로고·엠블럼 (logos/flags.generated.ts는 scripts/가 만들어요)
│  ├─ lib/                 공통 문구와 색, 훅, 사이트 정보, 테마
│  ├─ store/               game-store.ts: 화면과 엔진을 잇는 상태 저장소 (게임 상태)
│  ├─ query/               TanStack Query 클라이언트·Provider (서버에서 가져오는 데이터)
│  └─ leaderboard/         랭킹 API 타입·날짜 규칙(서버와 같이 써요), 브라우저 클라이언트, 쿼리 키·쿼리
├─ game/                   게임 엔진 (순수 TypeScript). 밖에서는 index.ts로만 가져와요
│  ├─ core/                타입, 공통 상수·룰셋 버전, 난수, 작은 도우미
│  ├─ player/              후보 생성, 플레이 유형·외모, 오버롤·연봉, 히든 스탯, 능력치 범위
│  ├─ world/               리그·구단·학교, 국적별 진로, 상 이름, 드래프트, 국가대표, 병역, 시즌 순위표
│  ├─ season/              시즌 진행·성장·시상, 결승 중계, 오프시즌, 이벤트, 진로·계약 결정
│  ├─ economy/             시즌 투자, 상점·기부
│  ├─ career/              은퇴·커리어 요약, 소식·수상 기록, localStorage 저장
│  └─ legacy/              랭킹 점수, 역대 기록 순위표, 닮은 꼴 선수, 업적
└─ server/                 서버 전용 (익명 플레이어 인증, 의견 보내기)
   ├─ db/                  DB 연결, 테이블 정의 (players, careers)
   └─ leaderboard/         순위표·스탯 랭킹 조회, 기록 저장, 제출·조회 검사
```

## 게임 규칙 요약

- **능력치**: 슛, 볼 핸들링, 패스, 수비, BQ, 운동능력 여섯 가지예요. 리바운드는 따로 없고 키·윙스팬·운동능력·수비·BQ에서 나와요.
- **선수 생성**: 첫 화면에서 "커리어 시작하기"를 누르면 한 단계씩 진행해요. 캐릭터를 먼저 고르고, 포지션과 후보 셋 중 하나를 고른 뒤 이름·등번호·국적·고등학교(또는 무작위)를 정해요. 고등학교는 국적에 맞는 실제 농구 명문 중에서 고르고(유럽은 구단 유소년 아카데미), 고교 시즌 상대도 같은 나라 학교예요. 국적은 국가대표 대회가 있는 10개국 중에서 고르고(기본 대한민국), 나라마다 대표팀 전력과 발탁 기준 오버롤이 달라요. 병역 의무는 대한민국 선수만 져요. 후보는 모두 오버롤 45로 시작하고, 플레이 유형마다 주특기는 55, 강점은 50, 보조는 47, 나머지는 45 언저리까지 시작해요. 이 상한은 후보를 뽑을 때마다 ±2씩 흔들려서, 같은 유형이라도 리롤하면 주특기가 53~57로 달라져요. 아주 드물게 가장 강한 능력치 하나만 5 더 높게 나와요. 키와 윙스팬도 유형에 맞춰 정해져요(예: 빅 가드 189–194cm). 오버롤은 포지션별 능력치 가중평균이에요.
- **챌린지 모드**: 첫 화면의 '오늘의 챌린지'에서 포지션을 고르면, 그날(한국 시간) 그 포지션에 정해진 선수로 시작해요. 플레이 유형·시작 능력치·키·윙스팬·잠재력·숨겨진 특성과 국적·고등학교가 누구에게나 같고, 이름·등번호·캐릭터만 골라요. 선수는 날짜와 포지션으로 만든 시드 난수로 뽑아서(`src/game/player/challenge.ts`의 `dailyChallenge`) 서버 없이도 모든 브라우저에서 같고, 매일 0시에 바뀌어요. 절반은 대한민국, 나머지는 다른 나라 국적이에요. 시작한 뒤의 시즌은 평소처럼 무작위라서, 같은 선수로 누가 더 잘 키우는지 겨뤄요. 은퇴하면 일반 랭킹과 함께 그날 그 포지션의 챌린지 랭킹에 올라가요(아래 "온라인 랭킹").
- **히든 스탯**: 여러 능력치가 고르게 적당한 선수보다, 특정 능력치가 두드러진 선수를 더 높게 평가해요. 어떤 조합이 히든 스탯이 되는지, 조건이 무엇인지는 게임 안에서 보여주지 않아요. 조건을 처음 채우면 시즌 결산 소식으로 히든 스탯 이름과 함께 알려주고, 그때부터 능력치 패널에 나타나요. 히든 스탯은 출전 시간·계약 제안·드래프트·연봉·시상에 쓰이는 평가 오버롤을 올리고(화면의 오버롤은 그대로), 기록에도 작은 효과를 줘요. 개발용 조건과 수치는 `src/game/player/specialty.ts`에 있어요.
- **성장**: 나이, 출전 시간, 활약, 훈련 초점, 숨겨진 특성(19세에 공개)이 영향을 줘요. 잠재력이 상한이에요. 출전 시간은 10대에는 영향이 작고, 19~20세에 걸쳐 서서히 커져 21세부터 성인 기준이 돼요. 21세부터 출전 시간이 적으면 잠재력이 깎여요. 30~32세는 능력치를 거의 그대로 유지하고, 33세부터 나이로 떨어지기 시작해 30대 중반을 넘으면 해마다 더 크게 떨어져요. 단, NCAA 선수는 벤치에 있어도 잠재력이 깎이지 않고, 강도 높은 팀 훈련 덕분에 프로에서 경기당 11분쯤 뛴 만큼은 크며, 코칭 덕분에 성장이 1.2배예요. 호주 NBL의 21세 이하 선수(육성 선수·Next Stars)도 비시즌에 주(州) 리그에서 뛰어서, 벤치에 있어도 그만큼은 크고 잠재력이 깎이지 않아요. 프랑스 LNB·스페인 ACB·ABA 리그의 21세 이하 선수(에스푸아·유스 팀)도 같아요. 농구 강국은 육성 환경이 좋아 22세까지 더 빨리 커요(호주·스페인 1.25배, 프랑스 1.2배, 세르비아·미국 1.15배, 캐나다 1.05배. 아래 "국적별 진로").
- **진로**: 고교(3년) → 대학(NCAA 또는 자국 대학 리그) 또는 자국 신인드래프트 고졸 참가 → 프로. 리그 평균 오버롤은 고교 48, U-리그 58, NCAA 65, KBL 68, G리그 78, 유로리그 80, NBA 87이에요. 한국에서 NBA까지 가기가 그만큼 어려워요.
- **국적별 진로**: 대학 리그·프로 리그·신인드래프트는 국적마다 실제 진로를 따라요(`src/game/world/paths.ts`). 선수 생성 화면에서 국적을 고르면 그 나라의 진로를 한 줄로 알려줘요.

  | --- | --- | --- | --- | --- |
  | 대한민국 | U-리그 (58) | KBL (68) | KBL 신인드래프트 | 아시아쿼터: B.리그, 호주 NBL |

  | 필리핀 | UAAP (55) | PBA (67) | PBA 신인드래프트 | 아시아쿼터: B.리그, KBL |
  | 중국 | CUBAL (54) | CBA (71) | CBA 신인드래프트 | 아시아쿼터: B.리그, 호주 NBL |

  | 미국 | NCAA (65) | NBA, G리그 (78) | NBA 드래프트, 미지명이면 G리그·해외 | 외국선수: CEBL, PBA, KBL, CBA, B.리그, ABA 리그, LNB, ACB, 호주 NBL |

  - 자국 신인드래프트는 리그가 달라도 같은 공식이에요. 리그 평균 - 11이면 마지막 순위, 평균 + 4면 1순위이고, 지명 수는 구단 수 × 2라운드예요. 고졸 참가는 리그 평균 - 9부터 할 수 있어요.
  - 아시아쿼터: 외국선수와 따로 두는 아시아 선수 자리예요. 그 리그 평균 - 3(주전급)부터, 시장에 나올 때마다 리그마다 50% 확률로 1~2년 제안이 와요. 계약 선택지에 '아시아쿼터' 꼬리표가 붙어요.
  - 호주: 아시아에서 농구를 가장 잘하는 나라라서 대표팀 전력(82)과 자국 리그(NBL 76)가 아시아에서 가장 높고, 육성 환경이 좋아 호주 국적 선수는 22세까지 성장이 1.25배예요(`paths.ts`의 `youth`, 다른 나라는 1배). 그만큼 커야 자국 리그에서 주전으로 뛰어요. 고교를 마치면 NCAA(장학생·워크온, 워크온은 언제나 받아 줘요), NBL 육성 선수 계약(NBL 평균 - 14부터), Next Stars 계약(평균 - 9부터) 중에서 골라요. 국내 MVP는 드물지만(커리어의 약 16%) NBA 진출이 가장 많은 국적이에요(약 40%).
  - 유럽(프랑스·스페인·세르비아): 대학 리그와 신인드래프트가 없고 구단 유소년에서 바로 프로가 돼요. 구단 유소년을 마치면 NCAA(장학생·워크온), 자국 리그 유스 계약(프랑스는 에스푸아 계약. 리그 평균 - 14부터), 프로 계약(평균 - 9부터) 중에서 골라요. 세르비아 선수는 옛 유고 나라들이 함께 치르는 ABA 리그에서 뛰어요. 유로리그에 나가는 구단(레알 마드리드, FC 바르셀로나, ASVEL, 파르티잔, 츠르베나 즈베즈다 등)은 유로리그 목록에만 있어서, 자국 리그는 그 강팀들을 뺀 나머지 구단끼리의 리그예요. 그래서 리그 평균을 실제보다 조금 낮게 잡았고, 자국 리그에서 잘하면 유로리그 구단의 제안을 받아요. 세 나라 모두 육성 환경이 좋아 22세까지 더 빨리 커요(프랑스 1.2배, 스페인 1.25배, 세르비아 1.15배).
  - 미국: 고교를 마치면 NCAA로 가요(장학생·워크온, 워크온은 언제나 받아 줘요). NCAA를 마치면 NBA 드래프트에 나서고, 지명받지 못하면 G리그나 다른 나라 리그로 가요. 미국 선수의 자국 리그는 G리그라서 다른 국적(평균 - 9, 27세까지, 70% 확률)보다 넓게(평균 - 12, 30세까지, 언제나) 받아 줘요. 육성 환경이 좋아 22세까지 성장이 1.15배지만 국가대표 발탁 기준(86)이 가장 높아요.
  - 캐나다: 고교를 마치면 NCAA(장학생·워크온)나 자국 대학 U 스포츠로 가요. 대학을 마치면 여름 리그 CEBL 구단과 바로 계약해요(평균 - 12부터. CEBL은 2026년부터 드래프트 대신 구단이 대학 선수와 바로 계약하는 사이닝 데이를 해요). U 스포츠 졸업생이 그 기준에 못 미치면 팀 없이 시장에 나가요. 22세까지 성장은 1.05배예요.
  - 외국선수: 미국·캐나다 선수는 다른 나라 리그의 외국선수 자리로 가요. 구단마다 두세 명뿐이고 팀의 주축을 맡기는 자리라 그 리그 평균 - 3(주전급)부터 제안이 오고, 실력이 되는 리그 가운데 두 곳이 시장에 나올 때마다 1~2년 계약을 제안해요. 계약 선택지에 '외국선수' 꼬리표가 붙어요. 캐나다 CEBL은 구단마다 외국선수가 다섯 명이라 미국 선수도 평균 - 12부터 받아 줘요.
  - NCAA 학교의 인연: 고교를 마칠 때 NCAA 제안의 절반은 그 나라 선수가 많이 간 학교에서 와요(대한민국 데이비드슨·곤자가, 일본 곤자가·네브래스카, 호주 세인트메리, 캐나다 켄터키·곤자가·퍼듀·듀크·캔자스, 프랑스 곤자가, 스페인 미시간·UCLA, 세르비아 일리노이. `leagues.ts`의 `NCAA_TIES`).
  - 프로 선수의 NBA 드래프트: 22세 이하 프로 선수는 평가 오버롤이 NBA 평균 - 7 이상이거나 NBA 스카우트가 지켜보는 리그(호주 NBL, LNB, ACB, ABA 리그, 유로리그)에서 뛰는 21세 이하이고, 스카우트 예상이 지명권 언저리(68순위 안)면 오프시즌마다 NBA 드래프트 신청을 물어요. 신청은 한 번만 할 수 있고, 지명받지 못해도 계약이 남아 있으면 소속팀에 남아요. NBA 구단의 영입 제안은 KBL만이 아니라 모든 프로 리그에서 받아요.
  - 대학 리그는 자국 대학만 있어요(일본 선수는 U-리그에 가지 않아요). NCAA는 예전처럼 실력이 되면 어느 국적이든 갈 수 있어요. NCAA 학교는 22곳이에요.
- **진출 기준**: 드래프트 지명, 계약 제안, NCAA 진학, NBA 영입 제안은 모두 그 리그 평균에서 얼마나 떨어져 있는지로 정해요. 예를 들어 NBA 정식 제안은 NBA 평균 이상, 최저 연봉 제안은 평균 - 3, NCAA 스카우트 제안은 NCAA 평균 - 1부터예요. NCAA 선수는 NBA 스카우트가 지켜봐서 NBA 드래프트 평가가 4점(약 14순위) 높아요. 그래서 리그에 들어가면 제 몫의 출전 시간을 받지만, 들어가기가 어려워요. 리그 평균만 바꾸면 기준이 같이 움직여요(`src/game/season/decisions.ts`).
- **드래프트**: 신청하면 1순위부터 지명이 하나씩 불리는 진행 화면이 떠요. 스카우트 예상 범위에 들어서면 천천히, 내 이름이 불리기 직전에는 한 번 더 뜸을 들여요. NBA 지명 순위는 평가 점수 1점마다 3.6순위씩 오르고, 로터리(14순위)부터는 세 배로 가파르게 올라서 최상위 유망주는 1순위에도 지명돼요(`src/game/season/decisions.ts`의 `nbaPick`). 15순위 아래와 미지명 기준은 그대로예요.
- **NCAA 진학**: 해외 경로 고교 졸업생은 평가 오버롤이 NCAA 평균 - 5부터 장학생, - 10까지는 워크온으로 NCAA 제안을 받아요(졸업생 약 9%가 워크온). 국내 경로는 NCAA 평균 - 1부터 스카우트 제안이 와요.
- **국가대표**: 올림픽, FIBA 농구 월드컵, 대륙컵(아시아컵·유로바스켓·아메리컵), 아시안게임이 실제 개최 주기대로 열려요. 올림픽은 강호만 바로 본선에 가고, 나머지는 최종예선(조별리그 약체 → 준결승 중위권 → 결승 상위권, 우승 1팀만 본선)을 거쳐요. 대표팀 전력에는 선수가 발탁 기준을 넘는 만큼(최대 +7)이 더해지고, NBA 평균을 넘는 압도적인 선수는 약한 나라일수록 더 보태요(OVR 1마다 +0.6, 최대 +7. 대표팀 전력 70 이하는 그대로, 90이면 0). 다른 NBA 선수가 즐비한 강호보다 약한 나라에서 슈퍼스타 한 명의 몫이 커서, 대한민국도 OVR 95 이상이면 낮은 확률로 월드컵·올림픽 금메달을 노려요(월드컵 결승 진출 OVR 95 약 1.5%, OVR 99 약 4.5%. 결승은 결승 클러치로 정해지기도 해요). 국대체질은 대표팀 전력에 3.5를 더 보태요(`src/game/world/national.ts`).
- **병역**: 대한민국 선수만 져요. 23세부터 입대 시기를 묻고 28세까지 미룰 수 있어요. 상무(D리그에서 뛰며 평소처럼 성장)나 현역(경기 감각이 떨어짐)으로 한 시즌을 보내고, 전역한 다음 시즌은 초반을 지나(정규시즌 80%를 남기고) 합류해요. 입대 전 팀으로 돌아가면 코치 신뢰도 그대로 이어 가요. 아시안게임 금메달이나 올림픽 메달을 따면 병역 특례를 받아요(`src/game/world/military.ts`).
- **키 성장**: 10대에 키가 갑자기 크면 포지션 전환 제안을 받아요.
- **시즌 투자**: 시즌 계획에서 보유 자금으로 두 가지까지 투자해요. 개인 스킬 코치(성장 +5%), 웨이트·피지컬(운동능력), 회복 관리팀(부상 위험 -20%, 건강), 영양·수면 관리(건강, 노화 완화), 영상 분석관(BQ, 코치 신뢰). 비용은 연봉에 비례하고, 학생 선수는 시즌마다 용돈·후원금 600만을 받아요. 전담 트레이너·시즌 투자·상점 장비로 나이로 떨어지는 폭을 줄이는 효과는 모두 겹쳐도 0.75배까지예요.
- **시즌 진행**: 시즌 계획에서 훈련 초점과 투자를 고르고 시작하면, 프리시즌 → 정규시즌 한 경기씩 → 플레이오프(전국대회) 한 라운드씩 → 결산 순으로 저절로 흘러가요. 1배속이면 한 시즌이 30초 남짓이고, 일시정지·2배속·4배속·건너뛰기(결정이나 결승까지)가 있어요. 홈 탭에서 경기마다 상대·점수·내 기록과 시즌 평균이 쌓여요. 팀 승수와 부상은 시즌을 시작할 때 정해 두고 경기마다 나눠 보여줘서, 한 번에 계산하던 때와 밸런스가 같아요. 무소속·군 복무 시즌은 경기 대신 일정(훈련, D리그, 복무…)을 한 칸씩 지나요. 시즌 도중 저장해도 불러오면 멈춘 채로 이어져요.
- **시즌 결산**: 시즌이 끝나면 오프시즌 전에 시즌 결산 화면(시즌 리포트·순위표·커뮤니티)으로 넘어가요. 순위표는 그 시즌 리그 정규시즌 순위예요(NBA는 컨퍼런스별, 다른 컨퍼런스로 바꿔 볼 수 있어요). 오프시즌 홈의 시즌 결과 카드에서 다시 열 수 있어요. 다른 팀 성적은 기록하지 않고 커리어와 연도로 정하는 난수로 그때마다 똑같이 만들어서(`src/game/world/standings.ts`), 저장 용량과 시즌 진행의 난수 흐름은 그대로예요. 내 팀 승패, 플레이오프 진출 여부(NBA·유로리그·G리그 8위, KBL 6위까지)와 KBL 4강 직행(1·2위), 플레이오프에서 만난 팀이 진출선 안에 있는 것까지 시즌 결과와 맞춰요. 아마추어 리그는 진출선이 없어요.
- **플레이오프 기록**: 플레이오프(아마추어는 전국대회 본선) 라운드를 공개할 때 그 라운드에서 내가 뛴 경기 기록(출전 시간·득점·리바운드·어시스트·스틸·블록)을 정해요. 7전 4선승제는 시리즈 경기 수만큼, 단판은 한 경기예요. 정규시즌 경기당 기록을 중심으로 흔들리고 경기력·지친 몸을 반영하며, 주전은 출전 시간이 8% 늘고 15분 아래 벤치는 25% 줄고 득점은 강팀을 만나 5% 줄어요. 라운드를 시작할 때 결장 중이면 그 라운드는 뛰지 못해요. 결승 중계를 틀었으면 결승 마지막 경기는 중계의 내 기록을 그대로 써요. 커리어 id·연도·라운드로 정하는 난수를 써서 시즌 진행의 난수 흐름과 밸런스는 그대로예요(`npm run balance` 결과가 같아요). 시즌 기록에 플레이오프 경기 수·경기당 기록·팀 승패가 정규시즌과 따로 남고(`SeasonRecord.po`), 랭킹 점수와 역대 기록 순위표는 지금처럼 정규시즌만 봐요. 기록 탭과 은퇴 화면의 '플레이오프 기록'에 프로 플레이오프 통산 평균(예: 21경기 평균), 고교·대학 전국대회 본선 통산, 시즌별 표가 나오고, 시즌 결산 리포트에 그 시즌 플레이오프 스탯과 통산 평균이 나와요. 시즌별 기록 표에는 스틸·블록 칸이 있어요. 이 기능 전에 치른 시즌의 플레이오프는 기록이 없어요.
- **플레이오프 업적**: 업적 창의 '플레이오프' 묶음 7종(모두 107종)이에요. 봄 농구 단골(프로 플레이오프 13시즌 진출, 기록이 생기기 전 시즌도 성적으로 셈), 플레이오프 철인(통산 120경기), 미스터 플레이오프(통산 3,000득점), 빅게임 헌터(NBA 플레이오프 한 시즌 평균 30득점), 플레이오프 모드(플레이오프 평균 득점이 그 시즌 정규시즌보다 7점 이상 높음), 통곡의 벽(한 시즌 평균 스틸 3개·블록 3개), 무결점 우승(NBA·KBL 플레이오프 모든 시리즈 4-0 우승). 한 시즌 평균을 보는 업적은 8경기 이상 뛴 시즌만 쳐요. 무작위 선택 커리어 600개에서 저마다 4~9% 커리어가 따요(`src/game/legacy/achievements.ts`의 `PO`).
- **체력과 부상**: 경기를 뛸 때마다 출전 시간만큼 건강이 닳아요(36분 에이스면 한 시즌에 NBA 약 51, KBL 약 41, 고교 약 30, 경기 사이 회복 전). 건강이 60 아래로 떨어지면 기록과 평점이 깎이고, 부상은 경기마다 그때 건강으로 굴려서 지칠수록 잘 다치고 더 심하게 다쳐요. 건강 50 이상이면 길어야 시즌의 22%, 30~49면 30%쯤 빠지고, 시즌 절반 넘게 빠지는 시즌 아웃급 부상은 건강이 30 아래일 때만 나와요. 시즌이 끝나면 닳은 만큼의 절반쯤 돌아와서, 매년 오래 뛰는 주전은 건강 80대에서 시즌을 시작해요(`npm run balance`의 pro health 줄).
- **빅매치**: 정규시즌 중반과 막판 순위 싸움에서 출전을 강행할지 고르는 결정이 생겨요. 건강할수록 성공하기 쉽고, 성공하면 경기력이 오르고, 실패하면 다쳐서 다음 경기에 나서지 못해요. 쉬면 건강을 회복하고 한 경기를 빠져요. 결승 직전에는 건강이 60 이하일 때만 '풀타임 출전을 강행한다'와 '출전 시간을 조절하며 뛴다' 중에서 골라요. 강행을 버텨 낼 확률은 지금 건강과 같아요(건강 40이면 40%, 특성은 따지지 않아요). 결정 창에도 이 확률을 적어 줘요. 성공하면 결승 기록이 오르고 파이널 MVP를 놓칠 확률이 1/5로 줄어요(60% → 92%, 승부사 85% → 97%). 실패하면 결승 도중 다쳐 일찍 빠져서 결승 기록이 줄고 결승 클러치를 맡지 못하며 파이널 MVP 확률이 0.6배(승부사는 0.8배)가 돼요(60% → 36%, 승부사 85% → 68%). 조절하며 뛰면 부상 위험 없이 확률이 그대로예요. 평균으로 따지면 보통 선수는 건강 약 43 이상에서 강행이 이득이고, 지쳐 있을수록 손해가 커져요(건강 0이면 0.6배). 승부사는 원래 확률이 높아서 건강 약 59 이상에서만 겨우 본전이에요. 부상 등으로 결승에 아예 결장하면 팀이 우승해도 파이널 MVP는 받지 못해요.
- **클러치**: 팀의 주전(예상 출전 26분) 이상이면 정규시즌 중 중요한 경기에서 마지막 플레이를 맡는 결정이 생겨요(주전은 시즌마다 한 번, 에이스(예상 출전 33분 이상)는 한 번이나 두 번(반반 확률). 정해 둔 경기에 결장 중이거나 다른 결정이 겹치면 다음 경기로 미뤄요). 클러치가 걸리면 화면 가운데 번개·불꽃 이펙트 뒤에 전광판(양 팀 엠블럼과 점수, 남은 시간)이 있는 결정 시트가 뜨고, 고르면 성공·실패 이펙트와 함께 최종 점수가 나와요. 상황은 세 가지예요.
  - **동점, 0:24 (45%)**: 주무기 하나와 공격 플레이 셋. 공격 플레이는 풀업 점퍼·돌파·패스·백도어 컷·풋백·3점슛·파울 유도 자유투·앤드원 여덟 가지예요.
  - **2점 뒤짐, 0:12 (30%)**: 주무기, 3점슛, 공격 플레이 둘. 3점슛·앤드원은 성공하면 바로 역전승이고, 2점짜리는 성공해도 동점이라 연장전에서 한 번 더 승부해요(오버롤이 리그 평균보다 높을수록 연장에서 이기기 쉬워요).
  - **2점 앞섬, 0:08 (25%)**: 상대의 마지막 공격을 막는 수비 넷. 에이스 수비·블록슛·차징 유도·기습 트랩·패스 길목 가로채기 다섯 가지 중에서 나와요. 막지 못하면 3점을 맞고 1점 차로 져요.

  **주무기**는 가장 높은 공격 능력치(수비 제외)로 정해지는 가장 자신 있는 무브예요. 가드·스몰포워드는 스텝백 3점슛·크로스오버 풀업·노룩 패스·턴어라운드 페이더웨이·덩크, 빅맨은 하이포스트 페이더웨이·페이스업 돌파·컷인 패스·포스트업 훅슛·파워 덩크이고, 같은 능력치의 보통 플레이보다 성공하기 쉬워요. 3점슛·트랩은 어렵지만 잘하는 선수일수록 더 유리하고, 파울 유도 자유투는 능력치에 덜 갈리는 안전한 선택이에요. 어떤 능력치를 쓰는 플레이인지는 보여주지 않고, 고른 플레이의 능력치가 리그 평균보다 높을수록 성공하기 쉬워요. 마지막 플레이에 성공하면 그 능력치가 +1, 경기를 이기면 경기력이 올라요. 경기 기록에 '클러치'(연장까지 갔으면 '연장') 표시가 남아요.
- **결승 클러치**: 결승에 오른 시즌에 주전이면 35%, 에이스면 60% 확률로 우승이 걸린 마지막 플레이를 맡아요(출전 강행 결정 다음). 7전 4선승제(NBA·KBL)는 3승 3패로 맞선 7차전, 단판 결승은 그 경기예요. 상황과 플레이는 클러치와 같고, 성공하면 우승(시리즈 4-3), 실패하면 준우승(3-4)으로 정해져요. 마지막 플레이로 결승이 끝났으니 결승 문자 중계는 다시 틀지 않아요(결승 클러치가 없는 결승은 전처럼 중계해요). 국가대표 대회도 결승에 오르면 대표팀 주전(발탁 기준 +5 이상)·에이스(+10 이상)가 같은 확률로 금메달이 걸린 결승 클러치를 맡고, 메달과 병역 특례는 클러치 결과로 정해요. 대표팀 결승은 상대가 세계 정상급이라 발탁 기준 +6 수준과 능력치를 견줘요. 결승 클러치는 어두운 경기장에 엇갈리는 스포트라이트와 떠오르는 트로피(국가대표는 금메달), 카메라 플래시 이펙트로 시작해 금테 전광판에 결승 이름이 붙고, 성공하면 트로피와 축포 속 'CHAMPIONS!'('GOLD!'), 실패하면 빛바랜 트로피와 '준우승'('은메달')이 떠요.
- **연봉 협상**: FA·이적·NBA 영입 제안을 고르면 바로 서명하지 않고 협상해요. 제시안 서명, 10% 인상 요구(거절되면 원래 조건), 25% 인상 요구(거절되면 구단이 떠나 다른 선택지로 돌아감), 계약 기간 1년 연장 요구 중에서 골라요. 성공 확률은 그 리그 수준 대비 오버롤, 지난 시즌 평점, 에이전시로 정해지고 숫자 대신 "협상력"으로 보여줘요. G리그 계약과 NBA 최저 연봉은 협상하지 않아요.
- **되묻기**: 이적·재계약·입단할 팀을 고르거나 위약금을 내고 계약을 해지할 때는 "정말 ~할까요?"로 한 번 더 물어요.
- **이적 요청**: 계약 기간 중에도 시즌 사이(오프시즌마다 한 번) 홈 탭의 계약 카드에서 이적을 요청할 수 있어요. 출전 시간이 적으면 구단이 쉽게 보내 주고, 팀의 핵심이거나 코치 신뢰가 높으면 붙잡아요. 허락되면 다른 구단 제안을 받고, 거절되면 코치 신뢰가 떨어지며 남은 연봉의 절반을 위약금으로 내고 FA가 될 수 있어요.
- **자금 쓰기**: 시즌 사이 홈 탭의 상점에서 보유 자금으로 물건을 사요. 상품은 31가지이고, 시즌마다 그중 6개(1억 미만·1억~20억·20억 넘게에서 두 개씩)가 진열돼요. 진열은 시즌이 바뀔 때마다 새로 정해지고, 이미 가진 상품은 다시 나오지 않아요. 상품은 장비(능력치 하나의 성장 +6% 등), 회복·생활(시즌 뒤 건강, 체력 소모, 부상 위험, 노화 완화), 사치품(기분 전환), 일회성(진열될 때마다 다시 살 수 있는 가족 여행·전지훈련 등), 유산(재단·아카데미처럼 은퇴 기록에 남는 것)으로 나뉘어요. 상품마다 아이콘이 붙어요. 보유 중인 아이템과 효과는 같은 칸에서 언제든 볼 수 있어요. 유소년 농구 기부(1,000만·1억·10억·100억)는 금액마다 한 시즌에 한 번 할 수 있고, 일정 확률로 금액에 맞는 보답이 와요(1,000만: 건강 +5와 시즌 시작 경기력 상승, 1억: 무작위 능력치 1개 +1, 10억: 무작위 능력치 2개 +1과 시즌 시작 경기력 상승, 100억: 무작위 능력치 3개 +1과 건강 +10). 확률은 오버롤과 금액으로 정해요(1,000만·1억·10억·100억 순서로 오버롤 70 이하 70·50·50·50%, 80 이하 60·40·40·33.3%, 90 이하 50·33·33·25%, 그 위 40·10·8·5%). 33세부터는(능력치가 떨어지기 시작하는 나이) 보답으로 능력치가 오르지 않고, 능력치 +1 하나마다 건강 +3이 와요. 상품 목록은 `src/game/economy/shop.ts`에 있어요.
- **시즌 중 이벤트**: 정규시즌 초중반과 후반에 한 번씩 50% 확률로 슬럼프, 라이벌 도발, 연전 피로, 스카우트 관전, 기자회견(대학·프로. 열애설·불화설 질문 포함), 메시지 유출 같은 결정이 생겨 시즌이 잠시 멈춰요. 고른 결과는 남은 경기의 경기력(기록·평점)이나 결장 경기 수에 반영돼요. 오래 쉬어야 하는 부상(6경기 이상)을 당하면 서둘러 복귀할지, 완전히 회복할지 골라요.
- **생활 이벤트**: 오프시즌마다 45% 확률로 단계에 맞는 이벤트가 생겨요. 고교는 장기자랑·시험·수학여행·체육대회 계주·사물함 편지, 대학은 학점·NIL 후원·해외 캠프·유니버시아드 선발전, 프로는 훈련 방식·에이전시·SNS 논란·주장 제안·시그니처 농구화·지인의 투자 권유 같은 일이에요. 연애·사생활 이벤트(열애설·캠퍼스 커플·이별·늦은 밤 목격담·결혼 발표)도 있어요(시즌 중 이벤트를 합쳐 71가지). "도전" 선택지는 결과가 운에 달려 있어요. 대형 에이전시(연봉 제안 +10%)와 전담 트레이너(맡은 능력치 성장 +15%)는 커리어 내내 효과가 남아요.
- **은퇴**: 30세부터 직접 선언할 수 있고, 40세에는 은퇴해요. 프로 경력이 있는 선수는 명예의 전당에 올라가요. 은퇴하면 엔딩 전에 커리어 회고가 나와요. 선수 캐릭터가 커리어 길을 따라 걸어가며 입단부터 시즌마다의 활약, 메달, 드래프트를 한 칸씩 보여주고 경기·득점·트로피가 쌓여 올라가요. 우승·MVP·금메달은 금색으로 빛나며 조금 더 오래 머물러요. 빠르게(3배속)와 엔딩 바로 보기가 있어요.
- **레거시 등급**: 은퇴하면 NBA MVP·우승·파이널 MVP·베스트 팀·다른 리그 MVP·올스타·개인상·최고 오버롤·통산 득점으로 매긴 레거시 점수(`legacyScore`)로 열 단계 등급을 받아요. 위에서부터 역대 최고 논쟁의 주인공(점수 600 이상·NBA MVP 5회 이상), 한 시대를 지배한 슈퍼스타(400·MVP 3회), 명예의 전당 1순위 헌액(260), 명예의 전당 헌액(180), 리그의 레전드(120), 올스타급 커리어(75), 팀의 든든한 주전(40), 오래 사랑받은 베테랑(프로 10시즌), 묵묵한 롤 플레이어(5시즌), 프로의 꿈을 이룬 선수이고, 프로 무대를 밟지 못하면 코트를 사랑한 선수예요(`src/game/career/career.ts`의 `LEGACY_TIERS`). 무작위 선택 커리어 3,000개에서 가장 흔한 등급도 22%를 넘지 않아요. 이 브라우저에 저장된 은퇴 기록은 읽을 때 지금 기준으로 다시 매기고, 서버는 예전 여섯 단계 등급으로 올라온 기록도 받아 지금 등급으로 바꿔 저장해요. 이미 저장된 온라인 기록은 `npm run db:rescore`로 다시 매겨요.
- **닮은 꼴 선수**: 은퇴 화면에서 내 프로 커리어와 가장 닮은 실제 KBL·NBA 선수를 하나씩, 비슷한 선수 둘과 함께 보여줘요. 포지션, 경기당 득점·리바운드·어시스트, 그 리그에서 뛴 시즌 수, MVP·우승 횟수, 커리어 위상(최고 오버롤)을 비교해요. 그 리그에서 뛰지 않았으면 프로 커리어 전체로 "KBL로 치면", "NBA로 치면"을 보여줘요. 실제 선수 값은 반올림한 대략적인 성향이라 화면에 숫자로 띄우지 않아요.
- **역대 기록 순위**: 은퇴 화면에서 NBA·KBL 정규리그 통산 득점·리바운드·어시스트와 올림픽 통산 득점을 실제 역대 순위표에 끼워 볼 수 있어요.
- **시즌 시상**: 리그마다 실제 상 이름으로 줘요(예: NBA MVP (마이클 조던 트로피), KBL 베스트5). 수상은 리그 평균 대비 평가 오버롤과 출전 시간으로 정한 영향력에 운을 더해 정해요. NBA 개인상은 기록 문턱도 넘어야 받아요(경기당 득점 / 득점+리바운드+어시스트): MVP·올-NBA 퍼스트팀 20 / 32, 세컨드팀 19 / 31, 서드팀·파이널 MVP·컨퍼런스 파이널 MVP 17 / 29, 올스타 15 / 26. 퍼스트팀 감이어도 기록이 모자라면 기록이 닿는 팀으로 내려가요. NBA에서 리그 평균 + 2보다 잘하는 선수는 공격을 더 맡아 득점이 1마다 6%(최대 30%) 늘어요. 수치는 `src/game/season/season.ts`에 있어요.
- **명예의 전당 순위**: 랭킹 점수 → NBA MVP 횟수 → 최고 오버롤 → 프로 통산 득점 순이에요. 랭킹 점수는 리그별 MVP·우승·파이널 MVP·개인상(NBA에서 받은 상일수록 커요), 국가대표 메달과 출전, 프로 통산 기록, 최고 오버롤, NBA 진출을 더한 값이에요(`src/game/legacy/hall.ts`). 고교·대학에서 받은 상은 프로보다 작게 쳐요(NCAA 0.2배, U-리그와 아시아 대학 0.1배, 고교 0.05배). 프로 리그는 NBA 1, 유로리그 0.5, 호주 NBL 0.46, ACB 0.45, LNB 0.43, B.리그·ABA 리그 0.42, CBA 0.41, G리그 0.4, KBL 0.35, PBA 0.28, CEBL 0.15배예요. 온라인 랭킹도 같은 순서로 줄을 세워요.

밸런스를 바꾸려면 대부분 `src/game/world/leagues.ts`(리그 평균. 진출 기준과 연봉도 따라 움직여요), `src/game/core/data.ts`(포지션 가중치와 키 범위), `src/game/player/ratings.ts`(나이별 성장량, 연봉), `src/game/season/season.ts`(성장·스탯·시상 공식)를 보면 돼요. 바꾼 뒤에는 `npm run balance`로 분포를 확인하세요.

## 상태 관리

상태를 성격에 따라 세 곳에 나눠 둬요. 아래 "개선점"에 TanStack Query를 들인 이유와 바뀐 점을 정리했어요.

| 상태 | 맡는 곳 | 방식 |
| --- | --- | --- |
| 게임 상태 (커리어, 진행 팝업, 알림) | `src/shared/store/game-store.ts` | `useSyncExternalStore`로 만든 작은 전역 스토어. 화면은 `useGame()`으로 읽고 `gameActions`로 바꿔요. 실제 규칙 계산은 엔진(`src/game`)이 하고, 스토어는 커리어 복사본에 엔진 함수를 적용한 뒤 localStorage에 저장해요 |
| 서버에서 가져오는 데이터 (온라인 랭킹) | `src/shared/query/`, `src/shared/leaderboard/queries.ts` | TanStack Query. 순위표·스탯 랭킹·날짜별 등록 수·나의 기록을 쿼리로 불러오고 기억해요 |
| 화면 안의 상태 (창 열림, 탭, 고른 칩) | 각 컴포넌트 | `useState` |

전역 상태 라이브러리(Zustand, Redux 등)는 쓰지 않아요. 혼자 하는 게임이라 커리어 객체 하나를 엔진이 바꾸는 구조이고, 지금 스토어가 이미 같은 일을 해요.

### 개선점: 온라인 랭킹을 TanStack Query로

전에는 화면마다 `useState` + `useEffect`로 순위표를 불러오고 기억했어요. 랭킹 페이지에는 거의 같은 캐시 코드(응답 순서 꼬임 막기, 키별 기록, 다시 불러오기)가 두 벌 있었고, 명예의 전당은 따로 만든 캐시와 변경 알림을 썼어요.

| | 전 | 지금 |
| --- | --- | --- |
| 같은 순위표 | 명예의 전당과 랭킹 페이지가 따로 불러요 | 쿼리 키가 같으면 한 번만 불러 함께 써요 (예: 첫 화면 오늘의 명예의 전당 = 랭킹 페이지 '오늘') |
| 다시 열 때 | 랭킹 페이지는 열 때마다 처음부터 불러와요 | 1분 동안은 기억한 것을 바로 보여주고, 지나면 보여주면서 뒤에서 새로 불러와요. 1분이 지난 뒤 창으로 돌아올 때도 새로 불러와요(첫 화면 오늘의 명예의 전당은 돌아올 때마다) |
| 은퇴 기록이 올라간 뒤 | 명예의 전당에만 알림을 보내 다시 불러와요 | 랭킹 쿼리(`["leaderboard", …]`)를 모두 낡은 것으로 쳐서, 떠 있는 화면은 바로 새로 불러와요. 접속할 때 밀린 기록을 보낸 경우도 같아요 |
| 실패 | 바로 실패 표시 | 잠깐 끊긴 네트워크는 한 번 더 해 봐요. 10초 시간 초과는 다시 기다리지 않아요. 보여주던 순위표가 있으면 새로 부르다 실패해도 그대로 둬요 |
| 코드 | 화면마다 캐시·`live` 플래그·다시 불러오기 | 화면은 `useQuery(boardQuery(day, pos))` 한 줄. 불러오는 함수(`client.ts`)는 실패하면 오류를 던지기만 해요 |

- **파일**
  - `src/shared/query/query-client.ts`: 브라우저에서는 QueryClient 하나를 함께 써요. 그래서 React 밖(게임 스토어, 기록 제출)에서도 같은 기억을 비울 수 있어요. 서버 렌더링에서는 요청마다 새로 만들어요.
  - `src/shared/query/QueryProvider.tsx`: 레이아웃에서 앱을 감싸는 클라이언트 컴포넌트.
  - `src/shared/query/load-state.ts`: 쿼리 결과를 화면의 세 갈래(데이터 / 불러오는 중 / 실패)로 나눠요.
  - `src/shared/leaderboard/keys.ts`, `queries.ts`: 쿼리 키와 쿼리. 새 랭킹 API를 붙일 때는 여기에 쿼리를 더하고, 키는 `LEADERBOARD`로 시작하게 해요.
- **테스트** (`src/shared/query/__tests__/query.test.ts`): 화면 상태 나누기, 재시도 규칙, 쿼리 키, 기록이 올라가면 랭킹 쿼리를 비우고 실패하면 대기열에 남기는지 확인해요.
- **더 할 수 있는 것**: 게임 스토어는 `useGame()`이 스냅샷 전체를 돌려줘서, 무엇이 바뀌든 구독한 화면이 다시 그려져요. 지금은 구독하는 곳이 두 곳(`Game.tsx`, `RankingsScreen.tsx`)뿐이라 문제가 없지만, 느려지면 선택자를 받는 `useGame((s) => s.career)`를 더하면 돼요.

## 저장

진행 내용은 브라우저 localStorage에 자동 저장돼요. 다른 기기로 옮기는 기능은 없어요. 은퇴한 선수의 전체 커리어는 엔딩을 다시 볼 수 있게 최근 20명까지 따로 보관해요(`b2r-endings-v1`). 은퇴한 선수의 요약만 온라인 랭킹 서버에 올라가요.

마음에 들지 않는 은퇴 선수 기록은 첫 화면의 '내 은퇴 선수'나 랭킹의 '나의 기록'에서 휴지통 단추로 지울 수 있어요. 확인 창에서 지우면 이 브라우저의 명예의 전당(`b2r-hall-v1`)과 엔딩 보관함에서 빠지고, 온라인 랭킹에 올라간 기록도 지워요(`DELETE /api/careers/mine`). 서버가 안 되면 지울 커리어 id를 `b2r-delete-v1`에 남겨 두고 다음에 접속할 때 지워요. 딴 업적과 누적 기록은 그대로 남아요.

## 온라인 랭킹

은퇴 기록을 서버에 모아 전체·포지션별 순위, 역대 베스트 5, 스탯 랭킹을 보여줘요. 별도 서버 없이 Next.js Route Handler와 Postgres로 만들었어요. 설계와 단계별 계획은 [docs/online-leaderboard.md](docs/online-leaderboard.md)에 있어요.

- **DB**: [Supabase](https://supabase.com) Postgres(서울 `ap-northeast-2`)를 [Drizzle ORM](https://orm.drizzle.team)과 [postgres.js](https://github.com/porsager/postgres)로 써요. 서버는 Supabase 공유 풀러의 트랜잭션 모드(포트 6543)로 연결하고, 이 모드는 prepared statement를 못 써서 꺼요(`src/server/db/db.ts`). 인스턴스마다 연결은 하나만 쥐어요. Vercel 함수는 DB와 같은 서울 리전(`icn1`, `vercel.json`)에서 돌아요. 모든 표에 RLS를 켜고 정책을 두지 않아서, Supabase Data API로는 표를 읽고 쓸 수 없어요.
  - 2026년 11월에 Neon에서 옮겼어요. Neon 무료 플랜은 DB가 깨어 있던 시간으로 세는데(월 100 CU-시간, 5분 동안 쿼리가 없어야 잠들어요), 기록 제출이 하루 종일 이어져서 하루 22~24시간 깨어 있었어요. Supabase 무료 플랜은 깨어 있는 시간 한도가 없어요. 대신 DB 500MB, 데이터 전송 월 5GB 한도가 있어요(옮길 때 26MB, 한 달에 약 40MB씩 늘어요).
  - 옮길 때는 `npm run db:copy -- <보내는 쪽 환경 변수> <받는 쪽 환경 변수>`(`scripts/db-copy.mts`)로 받는 쪽에 없는 플레이어와 기록만 넣고 집계를 다시 셌어요. 서비스를 멈추지 않으려고 먼저 한 번 옮기고, 배포 DB를 바꾼 뒤 그사이 올라온 기록을 한 번 더 옮겼어요.
- **테이블** (`src/server/db/schema.ts`)
  - `players`: 익명 플레이어(기기). 브라우저가 토큰 원문을 갖고, DB에는 `TOKEN_SECRET`으로 만든 해시만 둬요.
  - `careers`: 제출한 은퇴 기록. 순위에 쓰는 값(랭킹 점수, NBA MVP, 최고 오버롤, 통산 기록 등)은 칸으로, 은퇴 요약 전체는 `summary`(jsonb)로 둬요. 플레이어마다 같은 커리어는 한 번만 받아요.
  - `career_counts`, `career_totals`: 룰셋·포지션마다 커리어 수·NBA 진출·NBA MVP, 기록을 올린 플레이어 수. `careers` 트리거가 맞춰 둬서 전체 수를 셀 때 `careers`를 훑지 않아요.
- **조회 성능**: 순위표·스탯 랭킹은 인덱스 순서로 상위 N개만 읽고, 순위는 "나보다 높은 기록 수 + 1"을 같은 인덱스로 세요. 기록이 많아져도 순위표 비용은 거의 그대로예요. 쿼리 테스트(`src/server/leaderboard/__tests__/queries.test.ts`)는 PGlite(WASM Postgres)에 마이그레이션을 넣고 돌려서 DB 없이도 `npm test`로 돌아요.
- **흐름**: 처음 기록을 올릴 때 익명 플레이어를 만들어 토큰을 localStorage(`b2r-player-v1`)에 둬요. 프로 무대를 밟고 은퇴하면 요약을 등록 대기열(`b2r-pending-v1`)에 넣고 보내요. 실패하면 다음에 접속할 때 다시 보내요. 서버가 안 되면 조용히 실패하고 게임은 오프라인으로 계속돼요. 선수를 만들 때 "은퇴하면 이름과 기록이 공개돼요"라고 알려요.
- **기록 검사** (`src/server/leaderboard/validate.ts`): 엔진이 낼 수 있는 모양과 범위인지(최고 오버롤, MVP 수와 수상 기록, 은퇴 나이, 레거시 등급 등) 봐요. 욕설이 들어간 선수 이름은 "익명의 선수"로 바꿔 올려요. 같은 플레이어는 1분에 한 번만 제출할 수 있어요. 기록을 서버에서 다시 돌려 보는 재생 검증은 아직 없어요(계획 2단계).
- **챌린지 순위** (`src/server/leaderboard/challenge.ts`): 챌린지 기록은 `careers`에 날짜(`challenge_day`)와 시작 포지션(`challenge_pos`)을 적어 두고, 그날 그 포지션 기록끼리만 줄을 세워요. 한 플레이어가 여러 번 도전했으면 가장 좋은 기록 하나만 순위에 넣어요. 순서는 일반 랭킹과 같아요. 하루치 챌린지 기록만 인덱스(`careers_challenge`)로 읽고, 일반 순위표와 같은 캐시 태그를 써요. 접수 기간은 시작한 날과 그다음 날까지예요(`src/shared/leaderboard/days.ts`의 `challengeOpen`). 서버는 기록을 다시 돌려 보지 않아서, 정해진 선수로 시작했는지는 아직 확인하지 못해요(재생 검증은 계획 2단계).
- **룰셋 버전**: 은퇴 기록에 그때의 밸런스 버전 `RULESET_VERSION`(`src/game/core/data.ts`)이 남아요. 지금은 3이에요(국적별 진로부터. 2는 NBA 시상 기록 문턱부터). 랭킹 화면과 순위 알림은 버전을 가리지 않고 모든 기록을 한 줄로 세우고, API는 `ruleset`으로 한 버전만 골라 볼 수 있어요.
- **캐시**: 순위표와 스탯 랭킹은 서버에서 캐시하고(`'use cache'` + `cacheTag("boards")`), 기록이 제출되면 바로 비워서 은퇴 직후에도 내 기록이 보여요. 순위표 GET 응답은 Vercel CDN이 5분 동안 들고 있어서(`src/shared/leaderboard/cdn.ts`) 보기만 하는 요청은 함수와 DB까지 오지 않아요. 기록을 올린 브라우저는 한동안 `fresh=` 쿼리로 CDN을 건너뛰어 내 기록을 바로 봐요. 브라우저에서는 TanStack Query가 불러온 순위표를 1분 동안 기억하고, 기록이 올라가면 비워요(위 "상태 관리").

| API | 하는 일 |
| --- | --- |
| `POST /api/players` | 익명 플레이어를 만들고 토큰을 돌려줘요 |
| `POST /api/careers` | 은퇴 기록 제출 (`Authorization: Bearer <토큰>`). 응답에 전체·포지션 순위를 담아요. 챌린지 기록이면 그날 챌린지 순위도 담아요 |
| `GET /api/boards?scope=current\|all&pos=&day=YYYY-MM-DD` | 순위표: 전체 Top 100(포지션을 고르면 Top 50), 베스트 5, 전체 통계. `day`를 주면 그날(한국 시간) 올라온 기록끼리 매긴 순위예요 |
| `GET /api/boards/days` | 날짜별 랭킹 등록 수: 최근 7일(한국 시간) 날짜마다, 그리고 올타임으로 올라온 기록(선수) 수와 그 기록을 올린 플레이어 수, 올타임 포지션별 기록 수. 랭킹 화면의 날짜 칩과 선수 만들기의 포지션 버튼에 보여요 |
| `GET /api/stats?stat=pts\|reb\|ast\|stl\|blk\|tpm\|don&day=YYYY-MM-DD` | 스탯 랭킹: 프로 통산 상위 50명(`don`은 커리어 누적 기부금, 기부한 커리어만). `day`는 순위표와 같아요 |
| `GET /api/challenge?day=YYYY-MM-DD` | 챌린지 순위표: 그날(한국 시간, 최근 7일) 포지션마다 상위 50명과 도전한 플레이어 수·기록 수. 플레이어마다 가장 좋은 기록 하나만 세요 |
| `GET /api/challenge/mine?day=YYYY-MM-DD` | 내 토큰의 그날 챌린지 성적: 도전한 포지션마다 가장 좋은 기록의 순위와 도전 횟수 |
| `GET /api/careers/mine` | 내 토큰으로 올린 기록의 지금 순위 (랭킹 페이지 '나의 기록') |
| `DELETE /api/careers/mine?career=<커리어 id>` | 내 토큰으로 올린 기록 하나를 지워요 ('나의 기록'의 기록 지우기). 다른 플레이어의 기록은 지우지 못해요. 응답은 `{ deleted }`예요 |
